# Отладка фризов при нажатии микрофона

## Что это

В плагин добавлено инструментирование: замеры по этапам обработки голосового пакета
и замер всего кадра. Пишется в `rev_debug.log`.

Предыдущие правки (отложенное событие `OnClientStartSpeak`, переиспользование буферов,
RAII-гард, `try/catch`) фриз **не устранили** — значит причина не в них.
Здесь — замеры фактом, чтобы не гадать дальше.

## Включение

В `server.cfg` (или через консоль сервера):

```
REV_Debug 1          // 0 = выкл (по умолчанию), 1 = только медленные + сводка, 2 = каждый пакет
REV_DebugMs 5        // порог «медленного» пакета в мс
```

Уровни:

| `REV_Debug` | Что пишется |
|---|---|
| `0` | ничего, накладных расходов нет |
| `1` | только пакеты дольше `REV_DebugMs` + сводка SUM раз в секунду |
| `2` | каждый пакет + сводка |

Рекомендую начать с `1` — лог компактный, а медленные пакеты видно сразу.

## Где лог

`<gamedir>/rev_debug.log`, например `cstrike/rev_debug.log`.
Если каталог игры недоступен для записи — `rev_debug.log` в рабочем каталоге сервера.

## Как снимать замер

1. Поставить `REV_Debug 1`, `REV_DebugMs 5`.
2. Зайти на сервер, нажать микрофон **один раз**, сказать пару слов, отпустить.
3. Дождаться фриза (если он есть).
4. Прислать `rev_debug.log` за этот промежуток.

Важно: нажимать микрофон нужно **один раз** — так в логе будет ровно одна строка
с `first=1`, и видно, что происходило именно в момент нажатия.

## Формат строк

### Пакет голоса

```
PKT t=18422ms p=5 codec=opus sz=405 first=1 burst=3 frames=6 gap=447253us total=4663us decomp=469 cb=1 soxr=201 comp=3965 send=3 dst=0 act=0 mask=0x0 ovf=0 steam=183 speex=228 dgram=0%
```

| Поле | Что означает |
|---|---|
| `t` | **время от загрузки плагина, мс** — совмещать с моментом фриза по секундомеру |
| `p` | индекс клиента-источника |
| `codec` | кодек источника: `silk`, `opus`, `speex` |
| `sz` | размер входящего пакета, байт |
| `first=1` | **первый пакет после тишины = нажатие микрофона** |
| `burst` | номер пакета в серии (интервал с предыдущим < 10 мс) |
| `frames` | **сколько 20-мс кадров в пакете** — видно, пачка это или одиночный кадр |
| `gap` | пауза с предыдущего пакета этого игрока, мкс |
| `total` | **весь разбор пакета, мкс** |
| `decomp` | декодирование источника |
| `cb` | **`g_OnDecompress` — подписчики (AMXX-плагины)** |
| `soxr` | ресемплинг: создание + работа |
| `comp` | кодирование в целевые кодеки |
| `send` | рассылка получателям |
| `dst` | сколько получателей реально получило пакет |
| `act` | сколько получателей было активно/подключено |
| `mask` | битовая маска `GetVoiceStream(0)` — кому вообще слать |
| `ovf` | сколько пакетов не влезло в датаграм |
| `dgram` | максимальная заполненность датаграма, % |

### Отброшенные пакеты

```
DROP t=18455ms p=5 reason=blocked sz=405
```

| Причина | Что значит |
|---|---|
| `busy` | повторный вход: пакет пришёл, пока разбирался предыдущий |
| `big` | размер больше 8192 байт — клиент отключён |
| `voiceoff` | `sv_voiceenable 0` |
| `blocked` | игрок заблокирован |

Early return'ы **до** гарда (не логируются, т.к. пакет не читается): `srcPlayer == nullptr`.

### Сетевые опкоды (все, не только голос)

```
NET t=18455ms p=5 opcode=14 voice=0 us=18342
```

Пишется **только если опкод дольше `REV_DebugMs`**. `voice=1` — наш `clc_voicedata`,
`voice=0` — любой другой (движение, стрельба, чат и т.д.).

🔴 **Это ключевая строка для поиска фриза вне голосового пути.**

### Сводка раз в секунду

```
SUM pkts=47 first=1 slow=0 max=183us avg=94us dgram_max=71% ovf=0
```

| Поле | Что означает |
|---|---|
| `pkts` | сколько пакетов разобрано за секунду |
| `slow` | сколько превысило `REV_DebugMs` |
| `max` | худший пакет за секунду |
| `dgram_max` | худшая заполненность датаграма |
| `ovf` | сколько пакетов не влезло в датаграм за секунду |

### Кадр

```
FRAME total=1240us worst=1240us slow_ms=5.0
```

Пишется **только когда кадр дольше порога**. `total` — весь `StartFrame_PostHook`,
включая обработку `g_audio_waves` и подписчиков.

## Как читать результат

Логика простая, четыре случая:

**1. Есть `NET` с `voice=0` и большим `us`**
→ фриз в обработке **другого сетевого опкода** (движение, стрельба, чат). Смотреть номер опкода.

**2. Есть `FRAME` с большим `total`, медленных `PKT` нет**
→ фриз **не** в голосовом пути. Ищите в обработке `g_audio_waves`, в подписчиках
`StartFrame`, в других плагинах.

**3. Есть `PKT` с `first=1` и большим `total`**
→ фриз в разборе первого пакета. Смотреть, какое поле съело время:
- `cb` → виноваты подписчики `g_OnDecompress`;
- `soxr` → ресемплер (создаётся заново на каждый пакет);
- `comp` → кодеки;
- `decomp` → декодирование источника.

**4. Много `DROP`**
→ пакеты теряются молча. Смотреть причину: `busy` — значит разбор не успевает; `big` —
клиент отключается.

Если `FRAME`, `PKT` и `NET` все в норме (сотни мкс), а фриз есть —
значит он **вне плагина**: сеть, движок ReHLDS, другой плагин или сам клиент.

## Сборка

```bash
cd revoice-plus
mkdir -p build && cd build
cmake .. -DCMAKE_TOOLCHAIN_FILE=../linux-i686.cmake
cmake --build . -j$(nproc)
```

Результат — `out/revoice_plus_mm.so`, 32-бит.

## Что уже сделано в коде (для справки)

- П1: `g_OnClientStartSpeak` снят из обработчика пакета, вызывается в `StartFrame_PostHook`
  внутри существующего цикла
- П3: буферы в полях `CRevoicePlayer`, пакет по `const&`, `CodecTarget[2]` на стеке
- RAII-гард `ScopedVoiceBusy` от повторного входа
- `try/catch (std::bad_alloc)` вокруг `TranscodeVoice`
- `#include <vector>` в `revoice_player.h` (была ошибка сборки)
- Intel-флаги убраны из `CMakeLists.txt` (GCC их не понимает)
